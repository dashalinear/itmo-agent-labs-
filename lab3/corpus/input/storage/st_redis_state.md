# Состояние агента в Redis

Для отладки полезно хранить полную историю отдельно от рабочего представления контекста.

## Задача

Redis используют как быстрый кэш состояния между шагами агента.

Метрики хранилища включают задержку записи, размер базы и долю неудачных транзакций.

Чекпоинт фиксирует состояние после завершённого шага, поэтому восстановление начинается с границы шага.

## Персистентность

Без включённых AOF или снимков RDB состояние теряется при перезапуске сервера.

Ограничение: режим appendfsync everysec допускает потерю последней секунды записей [L-ST-08].

Чекпоинт фиксирует состояние после завершённого шага, поэтому восстановление начинается с границы шага.

Состояние агента включает историю сообщений, промежуточные результаты инструментов и служебные счётчики.

## Память

Ограничение: весь набор данных должен помещаться в оперативную память узла [L-ST-09].

При превышении maxmemory политика вытеснения удаляет ключи, поэтому для чекпоинтов используют noeviction [L-ST-10].

Состояние агента включает историю сообщений, промежуточные результаты инструментов и служебные счётчики.

Метрики хранилища включают задержку записи, размер базы и долю неудачных транзакций.
