## Назначение

SQLite используют для локального хранения чекпоинтов одного процесса: файл базы лежит рядом с проектом.

Для отладки полезно хранить полную историю отдельно от рабочего представления контекста.

## Режим журнала WAL

В режиме WAL читатели не блокируют писателя, а контрольная точка журнала выполняется фоном.

Ограничение: одновременно пишет только один процесс; второй писатель ждёт освобождения блокировки [L-ST-01].

Метрики хранилища включают задержку записи, размер базы и долю неудачных транзакций.

Чекпоинт фиксирует состояние после завершённого шага, поэтому восстановление начинается с границы шага.

## Ошибка ERR_LOCK_TIMEOUT при записи

Ошибка ERR_LOCK_TIMEOUT возникает, если блокировка не освобождается за 5 секунд; тикет CKPT-7731 описывает воспроизведение.

Ограничение: таймаут блокировки нельзя сделать бесконечным, иначе зависший процесс остановит всю задачу [L-ST-02].

Сетевые диски не поддерживают надёжные блокировки файлов SQLite, поэтому базу держат только на локальном диске [L-ST-03].

## Резервное копирование

Копию базы делают через backup API, а не простым копированием файла во время записи.

Ограничение: размер одной базы на учебном стенде не должен превышать 2 ГБ [L-ST-04].
