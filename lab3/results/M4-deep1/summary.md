## Решения и договорённости
*   План работы разбит на 5 шагов: поиск документов (L1), изучение лимитов (L2), поиск ответственных, уточнение выбора для DocSearch, сбор цитат и отправка результата.
*   Стратегия поиска: комбинация fulltext и vector search на уровне L1, затем чтение структуры документов через `get_l1`.
*   Для фиксации доказательств используется инструмент `cite_fragment` с указанием точных цитат и типов утверждений (fact, decision, limitation).

## Подтверждённые факты (с источниками)
*   **Redis** (`data/storage/st_redis_state.md`, doc_id: `72c0b078-4913-4a81-bdeb-794740e421f9`):
    *   Используется как быстрый кэш состояния между шагами агента [L-ST-08, ev_115e373c5968].
    *   Без AOF/RDB состояние теряется при перезапуске; `appendfsync everysec` допускает потерю последней секунды [L-ST-08].
    *   Данные должны помещаться в RAM [L-ST-09].
    *   При превышении `maxmemory` для чекпоинтов используется политика `noeviction` [L-ST-10, ev_502fc8dda0dd].
*   **PostgreSQL** (`data/storage/st_checkpoint_postgres.md`, doc_id: `e625cae6-6c4f-4673-87db-8839f34f778a`):
    *   Общее хранилище чекпоинтов для нескольких рабочих процессов; запись должна быть атомарной [L-ST-05, ev_60b770d1ac3d].
    *   Схема: таблица `checkpoints` (ключ `thread_id`, `checkpoint_id`) и `checkpoint_writes` [ev_5109ea8cc5af].
    *   JSONB-значения лучше держать меньше 1 МБ, большие артефакты выносят в объектное хранилище [L-ST-05, ev_5109ea8cc5af].
    *   Пул соединений ограничен 20 на процесс; при исчерпании возможны таймауты [L-ST-06].
    *   Миграции применяются до запуска процессов; откат после записи чекпоинтов невозможен без их потери [L-ST-07].
*   **SQLite** (`data/storage/st_checkpoint_sqlite.md`, doc_id: `63576563-7a76-4186-a023-d168b5d7873b`):
    *   Локальное хранение чекпоинтов одного процесса; файл базы лежит рядом с проектом [L-ST-01, ev_7f74b2d60cbb].
    *   Режим WAL: читатели не блокируют писателя, но пишет только один процесс [L-ST-01].
    *   Ошибка `ERR_LOCK_TIMEOUT` при неосвобождённой блокировке за 5 секунд (тикет CKPT-7731); бесконечный таймаут недопустим [L-ST-02].
    *   Сетевые диски не поддерживают надёжные блокировки [L-ST-03].
    *   Бэкап через backup API; лимит базы на учебном стенде — 2 ГБ [L-ST-04].
*   **DocSearch** (`data/projects/docsearch_architecture.md`, doc_id: `fd9485e7-df93-44b0-bc1f-b71d77ef235a`):
    *   Выбор бэкенда хранения чекпоинтов утверждён решением **РС-7** (протокол совещания M-12) [ev_5c0e749d74df].
    *   Политика резервных копий описана в регламенте хранения и решении РС-9.
