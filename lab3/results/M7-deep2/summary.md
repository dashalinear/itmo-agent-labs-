## Цель
Исследовать в корпусе подходы к хранению состояния агентов (agent state / persistence / memory), их различия по ограничениям (лимиты, деградация, потеря данных, производительность) и определить, какой подход выбран для проекта DocSearch.

## Ограничения пользователя
1. Найди все документы, описывающие подходы к хранению состояния агентов (чекпоинты, память, история диалогов, snapshots, event sourcing и т.п.) — используй L1-поиск (summaries) и L2-поиск, папки storage, agents, projects, meetings.
2. Для каждого найденного подхода: document_id, название, fragment_id, номера строк и точная цитата из L2-текста, описывающая подход и его ограничения (лимиты размера, время, количество, деградация, потеря данных).
3. Найди, какой подход выбран для DocSearch (решения совещаний, архитектура проекта) — с цитатами.
4. В конце дай: сравнительный список подходов с их ограничениями, выбранный для DocSearch вариант с обоснованием, и список открытых вопросов (что в корпусе НЕ подтверждено или противоречиво).

Формат ответа: структурированный отчёт с разделами «Подходы», «Ограничения каждого», «Выбор для DocSearch», «Открытые вопросы». Каждое утверждение — с подтверждением (document_id, fragment_id, lines, quote).

## Решения и договорённости
- План работы разбит на 4 шага: L1-поиск документов, поиск L2-деталей с ограничениями, поиск решения по DocSearch, составление отчёта.
- Используется многоуровневый поиск: vector (L1), fulltext (L1), grep (L1).
- Для подтверждения решений по DocSearch используются L2-цитаты из протокола M-12 и архитектурного документа.
- Проведён полный обзор папок `storage` (10 документов) и `agents` (11 документов) для выявления всех релевантных подходов.
- Выбраны для детального L2-анализа 4 дополнительных документа из папки `storage`: SQLite, долговременная память, векторная память, политика снимков.
- Для каждого из 4 подходов собраны L2-цитаты с конкретными ограничениями (лимиты размера, времени, количества, деградация).
- Выполнены L1-поиски по запросам "event sourcing журнал событий история диалога" и "Redis in-memory кэш состояния сессия" для выявления дополнительных подходов.
- Проведён детальный L2-анализ документов `st_redis_state.md` и `st_event_sourcing.md` для извлечения ограничений.
