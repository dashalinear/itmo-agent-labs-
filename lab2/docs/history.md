## Проблема → изменение → тест

| Что я увидела | Что поменяла | Тесты |
|---|---|---|
| A1, D1: решения АС пересказаны при статусе `completed` | критерий `verbatim_quotes`: полный текст проверенной цитаты и `стр. N` для каждого кода, иначе `paste_exactly` | `test_docs_artifacts_guard.py` |
| E1: резерв не освобождался при отмене во время вызова модели | прерванный вызов сразу освобождает резерв и учитывается как `interrupted_call_tokens` | `test_agent_harness.py` |
| B1: поисковики `ddgs` недоступны из сети ИТМО, ответ `web_fetch` целиком уходил в артефакт | `MultiProvider`: `ddgs` плюс публичные API, упавший дважды движок пропускается. Ответ `web_fetch` всегда умещается в лимит и показывает `artifact_id` страницы | `test_web_budget.py` |
| B2: все запросы до чтения, один URL из памяти модели | skill `research_web` и промпт требуют второй раунд; критерии `min_queries_after_reading`, `min_page_links_read`, `max_domain_share`. `select_sources` ставит в очередь только URL из выдачи или со страницы, которая уже прочитана (`not_discovered`). Другие исправления:
- Сервер LLM пропадал на минуты, а три попытки укладывались в секунды. Я добавила `llm_unreachable_wait_s` = 300: «Connection error» повторяется с паузами 2–30 с, бесплатно и без расхода `llm_retries`.
- Документ, прочитанный через `read_lines`, показывался с 0 страниц. Теперь страницы прочитанных строк попадают в реестр как `page_part`.
- Два параллельных `write_report_section` перезаписывали один `report.md` (WinError 32). Теперь отчёт отрисовывается под блокировкой на задачу.
- Одна строка решения сохранялась двумя evidence. Теперь на одно место приходится одно evidence (`already_saved` или `extended`).
- A1, B4 и C1 получали `completed` с открытыми шагами плана. Теперь `complete_task` требует закрытый план (`plan_open`).
- В B4 «Непроверенное» называло прочитанную статью непрочитанной. Теперь `complete_task` отклоняет такой раздел (`unverified_contradicts_queue`); отдельного теста на это нет.
- У параллельных tool calls одного шага не было общего ограничения времени. Я добавила `max_step_seconds`.
- Выгруженный JSON был одной строкой, и `read_artifact` видел только первые 5 000 символов. Теперь артефакт хранится построчно (`line_friendly`).
- `artifact_after_restart.py` искал только «АС-01», а `final_checks.py` не видел хитов выгруженного `search_excerpts`. Теперь контрольный факт ищется по всем опорным словам из `corpus/manifest.json`, а число хитов берётся из поля `total` в превью.

Позже, во время лабы 3, я нашла, что чтение из общего соединения SQLite вне блокировки иногда видело курсор параллельного запроса. Теперь чтения `TaskStore` тоже идут под блокировкой.
