## Подходы

**Гибридный поиск.** Основной подход — комбинация BM25 и векторной ветви: итоговая оценка `0,7·BM25_norm + 0,3·cosine`, веса пересматриваются не чаще раза в квартал [ev_b05767c19a4c] (справочник, стр. 261).

**Инфраструктура.** Эталонный кластер «Северный»: 12 первичных шардов с одной репликой; увеличение числа шардов — только через полную переиндексацию [ev_ae578b9b9b47] (справочник, стр. 4).

**Метрики качества.** Кафедра установила: основной показатель в домашних заданиях — nDCG@10, MRR — только для навигационных запросов [ev_f81aa99ecd15] (конспект, стр. 47).

**LLM-поиск.** В курсе разбирается подход с LLM-подтверждениями; окно контекста модели ограничивает объём подтверждений [ev_04489e8dff12] (конспект, стр. 89).

**Кэширование.** Кэш результатов запросов с лимитом и вытеснением LRU (после INC-2026-017 лимит 1 ГБ) [ev_3ce2e7f3f979] (отчёты, стр. 17).

## Ограничения

1. **Окно контекста LLM** ограничивает объём подтверждений в LLM-поиске [ev_04489e8dff12] (конспект, стр. 89).
2. **Перенос выводов между корпусами** без повторной оценки — частая ошибка студентов, повторяющийся комментарий преподавателя [ev_220d7b1e0f86] (конспект, стр. 1).
3. **Кэш результатов** не всегда снижает p95: при большом кэше паузы сборки мусора увеличивают хвост задержки [ev_fec677963eef] (отчёты, стр. 17).
4. **Изменение параметров ранжирования** без офлайн-оценки — урок из INC-2026-001 [ev_9e9e80ce7c8d] (отчёты, стр. 1).
5. **Масштабирование шардов** только через полную переиндексацию [ev_ae578b9b9b47] (справочник, стр. 4).

## Спорные утверждения

**1. «Полная переиндексация раз в сутки надёжнее инкрементальной»** (справочник, стр. 3) [ev_8cab4f46bd21].
- *За:* простота, предсказуемость, отсутствие накопления ошибок.
- *Против:* полная переиндексация — дорогая операция; при 12 шардах (АС-01) она блокирует масштабирование; инкрементальная индексация в современных движках зрелая.

**2. «Кэш результатов всегда снижает p95»** (отчёты, стр. 17) [ev_fec677963eef].
- *За:* кэш устраняет повторные вычисления, снижает нагрузку.
- *Против:* INC-2026-017 показал, что при лимите 2 ГБ паузы GC увеличили хвост задержки; утверждение не подтвердилось.

**3. Веса гибридного поиска 0,7/0,3** (справочник, стр. 261) [ev_b05767c19a4c].
- *За:* фиксация весов на квартал обеспечивает стабильность.
- *Против:* жёсткий квартал может быть слишком долгим для меняющихся корпусов; пересмотр весов требует офлайн-оценки (урок INC-2026-001).
