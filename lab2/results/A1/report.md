## Подходы

**Гибридный поиск.** Справочник описывает гибридную схему: итоговая оценка = 0,7·BM25_norm + 0,3·cosine, веса пересматриваются не чаще раза в квартал (АС-02, стр. 261) [ev_7a4c5df422ff]. Две ветви удваивают нагрузку на кластер (стр. 261).

**Масштабирование и отказоустойчивость.** Эталонный кластер «Северный» — 12 первичных шардов с одной репликой; увеличение шардов только через полную переиндексацию (АС-01, стр. 4) [ev_62b63fb9b27c]. При деградации векторной ветви (p95 > 450 мс дольше 10 минут) она отключается, запросы обслуживает только BM25 (АС-03, стр. 517) [ev_592fb8dc9b5c].

**Кэширование.** Кэш результатов применяется для снижения задержек, но, как показал разбор INC-2026-017, при большом кэше (лимит 2 ГБ) паузы сборки мусора увеличили хвост задержки (стр. 17) [ev_fec677963eef].

**Оценка качества.** Кафедра установила основной показатель качества в домашних заданиях — nDCG@10; MRR используется только для навигационных запросов (конспект, стр. 47) [ev_ccab4918fede].

**Обработка документов.** Документы больше 50 МБ не парсятся целиком — индексируются только первые 2000 страниц (стр. 2) [ev_15d5777c14c7]. OCR не выполняется (стр. 4) [ev_fd1cd1e47db6].

## Спорные утверждения

В справочнике найдено 87 упоминаний спорных утверждений. Ключевые:

1. **«Полная переиндексация раз в сутки надёжнее инкрементальной загрузки»** (стр. 3) [ev_50128f0ca141].
   - *За:* простота, предсказуемость, отсутствие накопления ошибок.
   - *Против:* высокая нагрузка на кластер, потеря актуальности между загрузками.

2. **«Дедупликацию лучше выполнять только после индексации»** (стр. 9) [ev_b2b0c4d2a8d3].
   - *За:* не замедляет индексацию, проще реализовать.
   - *Против:* дубликаты уже в индексе, требуют дополнительной очистки.

3. **«Кэш результатов всегда снижает p95»** — опровергнуто разбором INC-2026-017: при большом кэше паузы сборки мусора увеличили хвост задержки (стр. 17) [ev_fec677963eef].
   - *За:* кэш снижает задержку при повторных запросах.
   - *Против:* при большом кэше GC-паузы ухудшают p95.

## Ограничения

- **Размер документов:** документы больше 50 МБ не парсятся целиком — индексируются только первые 2000 страниц (стр. 2) [ev_15d5777c14c7].
- **OCR не выполняется** (стр. 4) [ev_fd1cd1e47db6].
- **Нагрузка гибридного поиска:** две ветви удваивают нагрузку на кластер (стр. 261).
- **Синонимы:** синонимы из словаря не учитывают контекст (стр. 82, 88).
- **Хранение позиций:** увеличивает размер индекса примерно на треть (стр. 100–130).
- **BM25:** оценки разных запросов несопоставимы, поэтому абсолютный порог релевантности по BM25 ненадёжен (стр. 136–154).
- **Векторный поиск:** плохо находит точные коды и редкие имена собственные (стр. 178).
- **Кэш:** при большом кэше паузы сборки мусора увеличивают хвост задержки (INC-2026-017, стр. 17) [ev_fec677963eef].

## Резюме

Документы в `data/search` описывают гибридную поисковую систему с BM25 и векторной ветвью. Ключевые решения архитектурного совета фиксируют параметры кластера (12 шардов), формулу гибридной оценки (0,7·BM25 + 0,3·cosine) и механизм деградации (отключение векторной ветви при p95 > 450 мс). Кафедра установила nDCG@10 как основной показатель качества. Разбор INC-2026-017 показал, что кэш результатов не всегда снижает p95 — при большом кэше GC-паузы ухудшают хвост задержки. Основные ограничения: размер документов (50 МБ / 2000 страниц), отсутствие OCR, удвоение нагрузки гибридным поиском, ненадёжность абсолютного порога BM25. Спорные утверждения (полная vs инкрементальная загрузка, дедупликация до/после индексации, эффективность кэша) требуют дальнейших экспериментов.
