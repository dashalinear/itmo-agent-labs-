## Цель
Собрать обзор по документам `data/search`: подходы, ограничения, спорные утверждения, решения АС-01/02/03, решение кафедры, разбор INC-2026-017. Индексировать 3 решения АС в Elasticsearch.

## Ограничения пользователя
- [C1] Каждый проверяемый вывод обзора ссылается на документ и страницу через evidence.
- [C2] Использовать только документы из data/search, без интернета.
- [C3] Обзор не длиннее 1200 слов.
- [C4] Спорные утверждения — отдельным разделом, с аргументами за и против.
- [C5] Решения архитектурного совета (АС-01, АС-02, АС-03) привести дословно с номером страницы.

## Решения и договорённости
- План: осмотр документов → поиск ключевых фраз → чтение страниц → сбор evidence → индексация в ES → написание обзора.
- Стратегия чтения: `search_text` для локализации, затем `read_lines` для точных выдержек.
- Harness hint: прекратить последовательное чтение, использовать `save_evidence` для найденных цитат, писать разделы отчёта, использовать `search_text` для оставшихся мест.

- **Спорное утверждение (Маркетплейс)**: «Полная переиндексация раз в сутки надёжнее инкрементальной загрузки. Контраргумент: Инкрементальная загрузка с проверкой хэшей даёт ту же полноту при меньшей нагрузке; полная переиндексация лишь маскирует ошибки учёта изменений.» (Источник: `data/search/search_engineering_handbook.md`, стр. 3, строка 41).
- **Спорное утверждение (Каталог)**: «Дедупликацию лучше выполнять только после индексации. Контраргумент: Дубли, попавшие в индекс, искажают статистику термов и выдачу; дешевле отсеивать их до записи.» (Источник: `data/search/search_engineering_handbook.md`, стр. 9, строка 141).
- **Спорное утверждение (Знания)**: «Стемминг всегда повышает качество поиска на русском языке. Контраргумент: Для коротких навигационных запросов стемминг иногда снижает точность: «Иванова» и «Иванов» сливаются в один терм.» (Источник: `data/search/search_engineering_handbook.md`, стр. 51, строка 837).
- **Спорное утверждение (Библиотека)**: «Стоп-слова нужно удалять при индексации ради экономии места. Контраргумент: Экономия места невелика, а фразовые запросы вида «в наличии» перестают работать.» (Источник: `data/search/search_engineering_handbook.md`, стр. 57, строка 935).
- **Подход (справочник)**: «Подход. Почти-дубли выявляются через шинглы и MinHash: документы с похожестью выше порога объединяются в кластер с одним каноническим представителем.» (Источник: `data/search/search_engineering_handbook.md`, стр. 3, строка 31).
- **Подход (справочник)**: «Подход. Для каждой версии документа вычисляется хэш содержимого; неизменённые документы не отправляются на переиндексацию.» (Источник: `data/search/search_engineering_handbook.md`, стр. 2, строка 15).
