Инструкция по работе с ветками git в учебных проектах

1. Основная ветка main защищена: прямые push запрещены.
2. Для каждой задачи создаём ветку feature/<номер-задачи>-<кратко>.
3. Коммиты небольшие, сообщение в повелительном наклонении: "Add loader for markdown".
4. Перед pull request делаем rebase на свежий main и прогоняем тесты.
5. Pull request ревьюит минимум один участник команды.
6. После слияния ветку удаляем.

Секреты (токены, пароли) никогда не коммитим: используем .env и .gitignore.
