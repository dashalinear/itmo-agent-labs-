# История разработки лабораторной 1

В `README.md` описано текущее состояние проекта и последний прогон, от 22.11.2026. Здесь я записала, что
менялось по дороге: что ломалось в пробных прогонах и что я исправила. Старые трассы `run_all_demos.ps1`
удаляет, поэтому всё ниже взято из моих заметок и из тех трасс, пока они ещё лежали в `traces/`.

## Прогоны

Первую цепочку демо-сессий я запустила 15.11. Потом были несколько пробных прогонов цепочки из шести сессий,
в них и нашлась большая часть ошибок, описанных ниже. 21.11 полная цепочка после исправлений прошла все проверки:
14 документов, 8 `indexed`, 17 выдержек. Тогда системный промпт ещё сам называл имена папок (`courses`, `projects`,
`meetings`, `howto`), а модель переименовала два одноимённых `notes.md` по содержимому. После этого я поправила
промпт и скрипты и записала прогон 22.11, он и лежит сейчас в репозитории.

## Что ломалось и что я поменяла

### Модель отвечала без вызова tool
В первой цепочке реплики 13–14 сессии main просят вызвать `head` с `n=0` и `read` с `../../secret.txt`, а модель
ответила сама, ничего не вызвав. Я добавила отдельную сессию guard (`demo/dialog_guard_ru.txt`), где каждая реплика
прямо просит вызвать инструмент и показать его ответ. Ходы в main я оставила, в следующих прогонах tool там вызывался.

### Ошибки MCP попадали в трассу как успех
`ToolGuardMiddleware` ставит `ToolMessage.status = "error"`, если ответ начинается с `{"ok": false`. Сначала я
проверяла только компактный JSON, а MCP-сервер отдаёт JSON с отступами, и ответы `es_unavailable` записывались
со `status: success`. Теперь регулярное выражение в `organizer/middleware.py` допускает пробелы и переводы строк,
тест в `tests/test_cli_script.py` проверяет оба формата.

### Отрицательный счётчик в `grep -r`
Пропущенная ссылка наружу вычиталась из числа просмотренных файлов, и в guard `grep -r input` (в `input` была только
ссылка) вернул `files_scanned: -1`. Я убрала это вычитание, теперь там `files_scanned: 0`.

### Лимиты срабатывали не в том порядке
Один вызов модели занимает 4 super-step. При `recursion_limit=100` цикл из 25 вызовов упирался в него раньше,
чем в `ModelCallLimitMiddleware`, и ход обрывался `GraphRecursionError` вместо понятной остановки. Я подняла
лимит до 110.

### Пустой ответ модели
В пробной сессии mcp_down модель закончила ход пустым текстом (у qwen так бывает, когда бюджет ответа уходит на
скрытые рассуждения). Теперь CLI
в таком случае печатает пометку `empty_answer_note` со списком tools, которые вернули ошибку. В последних прогонах
она не понадобилась.

### Заглушки MCP
Когда MCP-сервер не стартовал, `CatalogSyncMiddleware` всё равно проверял выдержки перед `upsert_excerpts`, и модель
несколько раз переделывала выдержки, которые всё равно некуда было записать. Ещё она один раз вызвала заглушку
вообще без аргументов, и было непонятно, к какому документу относится ошибка, поэтому инструкция по git осталась
`not_indexed`. Теперь у заглушек те же обязательные аргументы, что у сервера, проверка выдержек для них
пропускается, и они сразу отвечают `mcp_unavailable`. Строку JSON вместо списка в `excerpts` middleware тоже
разбирает. В последнем прогоне модель передала выдержки именно строкой, и статус стал `error`, как и должен.

Заодно я поправила `scripts/summarize_run.py`: пункт сводки «статус `error` после mcp_down» засчитывался по любому
документу с `error`, в том числе по семинару ReAct из сессии errors. Теперь сводка ищет документ, у которого в
`index_error` написано про недоступный MCP-сервер, и называет его.

### Категория в индексе после переноса
Если `update_document_path` вызывали без `category`, индекс оставлял категорию старой папки, хотя каталог уже
показывал новую. Теперь сервер всегда берёт категорию из папки `data/<category>/`, `CatalogSyncMiddleware` сверяет
и путь, и категорию, а `scripts/verify.py` сравнивает категорию каждой выдержки с каталогом.

### Опечатка в выдержке
Один раз модель трижды подряд получила `excerpt_validation_failed`, потому что переписала текст выдержки с опечаткой.
Код здесь отработал правильно, проверка для этого и нужна. В промпте и в `skills/index_excerpts/SKILL.md` я
подчеркнула, что выдержки из `build_excerpts` надо передавать без изменений.

### Параллельные `move`
Модель часто переносит много файлов за один шаг, и ToolNode выполняет эти вызовы параллельно. Запись каталога я
поставила под блокировку (`organizer/catalog.py`). Ещё на Windows `Path.resolve()` для папки, которую в этот момент
создаёт другой поток, может вернуть путь с префиксом `\\?\`, и проверка принадлежности workspace считала такой путь
внешним. Теперь `pathguard.py` снимает этот префикс.

## Правки перед последним прогоном
- Из системного промпта я убрала имена папок. В skill `organize_files` примеры имён остались (`courses`, `projects`,
  `meetings`, `howto`), и модель взяла их, плюс `_unsorted` для пустого файла. Одноимённые `notes.md` она на этот
  раз оставила под своими именами в разных папках. `fixtures/EXPECTED.md` я обновила под этот результат.
- В ответе на поиск модель должна цитировать текст выдержки в «» и указывать путь, строки и `document_id`
  (`organizer/prompts.py`, `skills/index_excerpts/SKILL.md`).
- `run_all_demos.ps1` делает `git commit` и `git push` только с ключом `-Push`, без него результаты только записываются.
